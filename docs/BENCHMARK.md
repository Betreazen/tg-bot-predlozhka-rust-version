# Потребление ресурсов: Python и Rust

Сервер: Debian 13, 2 vCPU, 3.8 GB RAM, cgroup v2. Сервер общий, на нём работают и другие
сервисы. Оба замера сняты в простое, с одним и тем же токеном и одними и теми же данными,
2026-09-30, с разницей примерно в 20 минут.

## Методика

- **Docker (Python).** Данные cgroup контейнера из `/sys/fs/cgroup/system.slice/docker-<id>.scope/`:
  `memory.current`, `memory.peak`, `anon` из `memory.stat`, `pids.current` и `usage_usec`
  из `cpu.stat`.
- **systemd (Rust).** `systemctl show`: `MemoryCurrent`, `MemoryPeak`, `TasksCurrent`,
  `CPUUsageNSec`. RSS процесса — через `ps -o rss`. RSS больше cgroup, потому что в него
  входят общие страницы бинарника.
- **CPU двумя способами.** Средний с момента старта: CPU-секунды ÷ аптайм. «Окно»: разница
  CPU-секунд за 600 секунд подряд, в процентах одного ядра.

Скрипты замеров повторяют эти команды один в один. Python — в цикле по трём контейнерам,
Rust — одним `systemctl show` до и после `sleep 600`.

## Результаты

| | Python: бот + PostgreSQL + Redis | Rust |
|---|---|---|
| CPU за 10 минут | 1.561 + 0.437 + 0.899 = **2.897 %** ядра | **0.0081 %** |
| Средний CPU с момента старта | 1.482 % (16 сут) + 0.452 % + 0.912 % (27 сут) = 2.846 % | 0.021 % (13 минут, включая запуск) |
| Память (cgroup) | 47.6 + 15.1 + 4.2 = **~67 MiB** | **2.63 MiB** |
| Пик памяти | 244 / 28 / 18 MiB | 3.15 MiB |
| Процессы | 2 + 7 + 6 = 15 | 1 процесс, 2 потока |
| На диске | образы 315 + 316 + 653 MB, том PostgreSQL 47 MB | бинарник 13 MB, `bot.db` 72 KB |

Вывод. CPU в простое упал примерно в 350 раз, с ~2.9 % ядра до ~0.01 %. Память по cgroup
уменьшилась примерно в 25 раз.

Для Rust-версии пока есть только 10-минутное окно. Ориентир на длинном интервале —
бот опросов, перенесённый тем же способом (тот же стек teloxide + SQLite под systemd): за
4.7 суток он показал 0.0114 % CPU, память 9.5 MiB, пик 10 MiB. Его средний CPU за сутки
соответствует окну, измеренному здесь.

## Куда уходил CPU Python-версии

Сам процесс Python-бота за 11.5 суток потратил 125 CPU-секунд, это 0.013 % ядра. Остальные
~1.47 % cgroup контейнера — это Docker `HEALTHCHECK`: каждые 30 секунд он запускал
`python -m bot.utils.health`. Каждый запуск поднимал новый интерпретатор, импортировал
SQLAlchemy, pydantic и redis и подключался к PostgreSQL и Redis. Один прогон на сервере стоил
0.419 CPU-секунды: 0.419 / 30 = 1.40 % ядра. PostgreSQL и Redis добавляли собственные проверки
каждые 10 секунд и обслуживали эти подключения.

В Rust-версии периодических проверок нет. За процессом следит systemd (`Restart=always`),
а планировщик публикаций при пустой очереди ждёт сигнала, а не таймера.

## Что не измерено

- CPU Rust-версии за сутки и больше. Повторный замер: `systemctl show tg-bot-predlozhka -p CPUUsageNSec -p ActiveEnterTimestamp`.
- Нагрузка под потоком предложений. Сейчас их нет, в базе 13 пользователей и 0 предложений.
